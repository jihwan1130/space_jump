# SPACE JUMP — 우주 점프

지구에서 출발해 행성에서 행성으로 점프해 나가는 **Orbit / Circle Jump** 장르의 웹 게임 프로토타입.
라운드는 무한히 이어지고, 스테이지가 올라갈수록 난이도가 계속 상승합니다.

의존성 없는 단일 HTML 파일(Canvas 2D)이라 `index.html`을 브라우저로 열기만 하면 바로 실행됩니다.

## 실행

```bash
# 그냥 파일 열기
start index.html

# 또는 로컬 서버로
npx serve -l 4321 .
```

## 조작

- **탭 / 클릭 / 스페이스** — 점프
- **M** 또는 우측 상단 아이콘 — 사운드 토글

## 게임 규칙

1. 우주선은 행성의 점선 궤도를 따라 공전합니다.
2. 점프하면 **우주선이 향한 직선 방향(행성 중심 → 우주선) 그대로** 발사됩니다.
3. 날아가다 다음 행성의 점선 궤도 안에 들어가면 자동으로 착지해 공전을 시작합니다.
4. 빗나가면 그대로 우주 밖으로 날아가 실패합니다. (벽에 튕기지 않습니다)
5. **목성(스테이지 4)부터 화면이 저절로 계속 위로 올라갑니다.** 점프해서 화면이 밀려 올라가는 것과
   똑같은 움직임이, 멈춰 있어도 **천천히 쉬지 않고** 일어납니다. 화면 아래로 밀려나면 그대로 끝입니다.

실패 유형: `추락` · `궤도 이탈` · `우주 미아` · `소행성 충돌` · `행성 붕괴` · `화면 밖으로 밀려남`

## 점수 / 콤보

- 착지 = `10 × 콤보 배수`(최대 x9), 궤도 깊숙이 꽂아 넣으면 `PERFECT!` +15, 체크포인트 행성 +30
- 3.4초(`COMBO_WINDOW`) 안에 다음 행성을 잡으면 콤보가 이어지고, 3·5·8·12 콤보에서 칭찬 문구가 뜹니다
- 착지 시 충격파 링 · 점수 팝업 · 화면 펄스 · 콤보에 따라 음이 올라가는 착지음이 함께 재생됩니다

## 스테이지 / 난이도 곡선

행성 8개마다 스테이지가 오르고, 각 스테이지는 실제 태양계 순서를 따릅니다.

`지구 → 달 → 화성 → 목성 → 토성 → 천왕성 → 해왕성 → 명왕성 → 외계행성 → 심우주 N…`

스테이지가 오르면서 함께 변하는 값:

| 요소 | 변화 |
|---|---|
| 행성 크기 / 궤도 반경 | 점점 작아짐 |
| 우주선 공전 속도 | 행성 자전 속도 × `ORBIT_SPIN`(2.0), 스테이지가 오를수록 더 빨라짐 |
| 행성 간 거리 / 좌우 편차 | 점점 멀어짐 |
| 조준 표시선 | 지구(스테이지 1)에서만 표시 |
| 소행성 (궤도를 도는 장애물) | 스테이지 2부터 등장, 확률 증가 |
| 이동 행성 (좌우로 흔들림) | 스테이지 3부터 등장 |
| **화면 자동 상승** | **스테이지 4부터, 22 → 50px/s** |
| 붕괴 행성 (제한 시간) | 스테이지 5부터 등장 |

봇 시뮬레이션 기준 난이도 층위:

- 타이밍이 완벽한 봇: 화면 아래까지 항상 167px 이상 여유를 두고 스테이지 8까지 도달, 결국 소행성에서 끝남
- 매 점프마다 1.2초씩 머뭇거리는 봇: 여유가 58px까지 줄고 스테이지 5 부근에서 막힘
- 아예 멈춰 있으면 3~5초 만에 화면 아래로 밀려남

체크포인트(각 스테이지 첫 행성)는 크고 느려서 한숨 돌릴 수 있게 되어 있습니다.

## 카메라

착지한 행성이 화면 세로 78%(`CAM_ANCHOR`) 지점에 고정되어, 점프할 때마다 **직전 행성은 화면 밖으로 완전히 밀려납니다.**
카메라는 위로만 이동합니다.

스테이지 4부터는 `state.camTarget`이 매 프레임 `diff(stage).scroll`만큼 스스로 위로 올라가고,
카메라가 그걸 따라가면서 화면 전체가 계속 밀려 올라갑니다. 착지하면 카메라 앵커가 다시 78% 지점으로
잡히므로, 계속 점프해 올라가는 한 여유가 회복됩니다. 우주선의 화면 y가 바닥에 닿으면 사망합니다.

## 밸런스 튜닝

난이도 수치는 전부 `diff(stage)` 한 함수에 모여 있습니다. 여기 값만 바꾸면 곡선 전체가 조정됩니다.

콘솔에서 내부 상태에 접근할 수 있는 핸들도 열려 있습니다:

```js
window.__spacejump   // { state, jump, reset, diff, planetById, update, draw }
```

`update(dt)`를 직접 호출하면 화면 렌더링과 무관하게 결정론적으로 시뮬레이션할 수 있어,
봇을 붙여 스테이지별 난이도를 수치로 검증할 수 있습니다.
