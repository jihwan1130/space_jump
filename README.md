# SPACE JUMP — 우주 점프 (앱인토스 미니앱)

지구에서 출발해 행성에서 행성으로 점프해 나가는 **Orbit / Circle Jump** 장르 게임.
앱인토스 **WebView 미니앱**(SDK 3.x)으로 만들어져 있고, 그대로 `.ait` 번들을 뽑아 콘솔에 올릴 수 있어요.

일반 브라우저에서도 그대로 돌아가요. SDK 기능(식별키 · 저장소 · 햅틱 · 광고 · 화면 제어)은
토스 앱 밖에서는 자동으로 대체 구현으로 떨어집니다.

---

## 빠르게 시작하기

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # dist/ 생성 후 space-jump.ait 패키징
```

`npm run build`가 끝나면 프로젝트 루트에 **`space-jump.ait`** 가 생겨요.
이 파일을 앱인토스 콘솔 → **앱 출시** 메뉴에 업로드하면 QR로 토스 앱에서 테스트할 수 있어요.

---

## 프로젝트 구조

```
apps-in-toss.config.ts   앱인토스 설정 (appName · 내비게이션 바 · WebView 옵션)
vite.config.js           번들러 설정
index.html               캔버스 + DOM 오버레이 UI 껍데기
introduce.html           게임 소개 · 홍보용 단일 페이지
supabase/schema.sql      DB 테이블 정의 (한 번만 실행)
src/
├─ main.js               부트스트랩 — 미니앱 수명주기와 게임을 연결
├─ game.js               게임 본체 (물리 · 렌더 · HUD · 보석)
├─ skins.js              우주선 스킨 7종 (전부 캔버스 드로잉)
├─ platform.js           앱인토스 SDK 어댑터 (브라우저 폴백 포함)
├─ cloud.js              Supabase 연동 (프로필 · 기록 · 랭킹)
├─ nickname.js           닉네임 생성 · 욕설 필터 · 검증
├─ audio.js              WebAudio 신스 — 효과음 · 공간계 · BGM
├─ config.js             광고 ID · 보석 확률 · DB 주소 등 출시 전 확인할 값
└─ style.css             오버레이 UI 스타일
```

게임 코드는 SDK를 직접 부르지 않고 **전부 `platform.js`를 거쳐요.** SDK 버전이 바뀌거나
API 이름이 달라져도 이 파일 하나만 고치면 됩니다.

### 데이터베이스 (Supabase)

**처음 한 번은 반드시 직접 실행해야 해요.** publishable 키로는 테이블을 만들 수 없어요.

1. Supabase 대시보드 → **SQL Editor** → New query
2. `supabase/schema.sql` 전체를 붙여넣고 **Run**
3. 게임을 새로고침하면 랭킹이 뜨기 시작해요

> `permission denied for table players` (코드 42501)가 뜬다면 권한이 빠진 거예요.
> RLS 정책과 별개로 `anon` 역할에 테이블 GRANT가 있어야 PostgREST가 읽고 씁니다.
> `supabase/grants.sql`만 따로 실행하면 해결돼요.

| 테이블 | 담는 것 |
|---|---|
| `players` | 유저 식별키 · 닉네임(unique) · 보석 · 최고 기록 · 보유/장착 스킨 |
| `runs` | 한 판이 끝날 때마다의 기록 (점수 · 스테이지 · 보석 · 사망 사유) |

실행하기 전에도 **게임은 그대로 돌아가요.** 기록은 기기에 저장되고, 랭킹 화면에만
"아직 준비되지 않았어요"가 떠요. 서버가 죽어도 마찬가지예요.

동기화 규칙 — 로컬이 항상 먼저이고 서버는 백업이에요. 최고 기록은 큰 쪽을 남기지만,
**보석은 쓰는 재화라 max로 합치면 안 돼요** (기기 두 대로 같은 보석을 무한히 쓸 수 있어요).
그래서 서버 값을 따르되, 아직 못 올린 변화가 로컬에 있으면(`dirty`) 로컬을 지켜요.

> ⚠️ 로그인 절차가 없어서 클라이언트가 올리는 점수를 그대로 믿는 구조예요.
> 랭킹에 상금이 걸리는 등 신뢰가 중요해지면 Edge Function으로 검증을 옮기세요.

### 닉네임

정하지 않은 사람은 `우주미아0000` 형태를 자동으로 받아요. 식별키에서 번호를 뽑아
같은 사람은 늘 같은 이름이 되고, 겹치면 번호를 바꿔가며 최대 5번 다시 시도해요.

직접 지을 때는 한글·영문·숫자 2~12글자만 받고, `src/nickname.js`의 필터가
욕설·사칭어를 막아요. 숫자나 기호를 끼워 넣는 우회(`시1발`, `f u c k`)도 잡도록
비교 전에 공백·숫자·기호를 걷어내요. 중복은 DB의 unique 제약이 최종 심판이에요.
(확인과 저장 사이에 남이 먼저 가져갈 수 있어서, 저장 실패도 따로 안내해요.)

### 아이콘 규칙

**시스템 이모지를 쓰지 않아요.** 이모지는 기기·OS 버전마다 모양과 색이 달라서 같은 화면이
사람마다 다르게 보이거든요. 그래서 모든 아이콘은 직접 그려요.

| 자리 | 방식 |
|---|---|
| 사운드 토글 | `index.html`의 인라인 SVG (켬/끔은 CSS 클래스로 교체) |
| 신기록 반짝임 | `style.css`의 `clip-path`로 그린 별 |
| 경고 표지 | `game.js`의 `drawWarnSign()` — 캔버스에 직접 |
| 소개 페이지 삽화 | `introduce.html` 안의 캔버스 드로잉 |

## 출시 전에 꼭 해야 하는 일

### 1. `appName` 맞추기

콘솔에 앱을 등록할 때 입력한 `appName`과 아래 두 곳이 **완전히 같아야** 해요.

- `apps-in-toss.config.ts` → `appName`
- `src/config.js` → `APP_NAME`

지금은 둘 다 `space-jump`로 되어 있어요. 딥링크도 `intoss://space-jump`가 됩니다.

### 2. 리워드 광고 ID 교체하기

현재는 문서에 공개된 **테스트 ID**(`ait-ad-test-rewarded-id`)를 쓰고 있어요.

```bash
cp .env.example .env.production
# VITE_REWARD_AD_GROUP_ID=콘솔에서_발급받은_보상형_광고_그룹_ID
npm run build
```

> 테스트 ID로 출시하면 수익이 잡히지 않고, 반대로 **실제 ID로 개발 테스트를 반복하면 정책 위반**이에요.
> 개발 중에는 테스트 ID를 그대로 두세요.

### 3. 콘솔에서 설정해야 하는 것

코드로는 할 수 없고 콘솔에서만 되는 것들이에요.

| 항목 | 위치 | 안 하면 생기는 일 |
|---|---|---|
| 카테고리를 **게임**으로 등록 | 미니앱 정보 | `getUserKeyForGame`이 `INVALID_CATEGORY` 반환, 리더보드 동작 안 함 |
| 앱 아이콘 · 국문 이름 | 미니앱 정보 | 내비게이션 바 · 목록에 브랜드가 안 나옴 |
| 스크린샷 · 연령등급 · 개인정보처리방침 | 미니앱 정보 | 검수 반려 |
| 보상형 광고 단위 생성 | 인앱 광고 | 광고가 로드되지 않아 "이어하기" 버튼이 아예 안 뜸 |
| 게임 리더보드 활성화 | 게임센터 | "랭킹 보러 가기" 버튼이 숨겨짐 (`LeaderBoard not found`) |
| 고객센터 문의 채널 | 미니앱 정보 | 더보기 → 문의하기가 비어 있음 |

미니앱 정보 승인에는 영업일 기준 1~2일이 걸려요. 승인 전에는 리더보드 호출이 실패합니다.

## 게임 출시 가이드 대응표

[게임 출시 가이드](https://developers-apps-in-toss.toss.im/checklist/app-game) 항목별로 어디서 처리했는지 정리했어요.

### 접속 및 사운드

| 항목 | 구현 |
|---|---|
| 10초 이내 최초 화면 | 정적 번들(JS 약 110KB), 외부 요청 없음 |
| 배경음 · 효과음 · 햅틱 | `src/audio.js` (WebAudio 신스 BGM + SFX), `platform.haptic()` |
| 사용자가 사운드 On/Off | 좌측 하단 토글 버튼 + `M` 키. 설정은 세이브에 저장돼 다음 접속에도 유지 |
| 백그라운드 전환 시 사운드 즉시 종료 | `onVisibility` → `audio.suspend()` (AudioContext까지 정지) |
| 복귀 시 정상 재생 | `audio.resume()` + "이어서 하기" 화면 |

### UX 및 내비게이션 바

| 항목 | 구현 |
|---|---|
| 우측 상단 닫기 버튼 | 프레임워크 기본 제공. `navigationBar.transparentBackground` + `theme: 'dark'` |
| Safe Area 침범 금지 | `SafeAreaInsets.get/subscribe` → CSS 변수 + 캔버스 HUD 좌표에 모두 반영 |
| X 버튼과 겹치는 UI 없음 | HUD는 좌측 열에만, 사운드 토글은 좌측 하단. 우측 상단 `NAV_RESERVE_W`는 비워둠 |
| 진입 즉시 바텀시트 없음 | 타이틀 화면만 노출 |
| 모든 화면에서 나갈 수 있음 | 프레임워크 X + 게임 오버의 "그만하기" |
| CTA 예측 가능 | "게임 시작하기 / 다시 도전하기 / 광고 보고 이어하기 / 랭킹 보러 가기 / 그만하기" |
| 자사 서비스 유도 없음 | 외부 링크 없음 |
| 광고를 인트로·로딩·모달에 노출 안 함 | 게임 오버 화면에서 사용자가 직접 누를 때만 재생 |

| 항목 | 구현 |

| 항목 | 구현 |
|---|---|
| 인게임 풀스크린 | 논리 가로폭 480 고정 + 세로는 기기 비율을 따라감(`H_MIN`~`H_MAX`). 여백 없이 꽉 참 |

| 항목 | 구현 |

| 종료 후 음악 재개 | `audio.resume()` |

## 기기에서 꼭 직접 확인해야 하는 것

문서만으로는 확답이 안 되는 항목이에요. QR 테스트 때 눈으로 확인해 주세요.

1. **내비게이션 바 X 버튼을 눌렀을 때 종료 확인 모달이 뜨는지.**
   X 버튼이 `backEvent`를 발생시키는지는 문서에 명시돼 있지 않아요.
   바로 닫힌다면 검수 대응을 위해 채널톡으로 문의가 필요할 수 있어요.
   (뒤로가기 버튼 · 제스처와 게임 내 "그만하기"는 모달을 확실히 거칩니다.)
2. **햅틱이 과하지 않은지.** 착지마다 `tickWeak`이 울려요. 거슬리면 `src/game.js`의 `haptic(...)` 호출을 줄이세요.
3. **광고 로드 소요 시간.** 애드몹이 선택되면 최대 60초까지 걸릴 수 있어요. 그동안은 "이어하기" 버튼이 안 보입니다.
4. **노치 · 다이내믹 아일랜드 기기에서 HUD 위치.**

## 게임 규칙

1. 우주선은 행성의 점선 궤도를 따라 공전해요.
2. 탭하면 **우주선이 향한 직선 방향(행성 중심 → 우주선)** 그대로 발사돼요.
3. 다음 행성의 점선 궤도 안에 들어가면 자동으로 착지해요.
4. 빗나가면 그대로 우주 밖으로 날아가 실패해요. (벽에 튕기지 않아요)
5. **목성(스테이지 4)부터 화면이 저절로 계속 위로 올라와요.** 아래로 밀려나면 끝이에요.

실패 유형: `추락` · `궤도 이탈` · `우주 미아` · `소행성 충돌` · `행성 붕괴` · `화면 밖으로 밀려남`

**점수** — 착지 = `10 × 콤보 배수`(최대 x9), 정밀 착지 `PERFECT!` +15, 체크포인트 행성 +30.
3.4초 안에 다음 행성을 잡으면 콤보가 이어져요.

**스테이지** — 행성 10개마다 상승. `지구 → 달 → 화성 → 목성 → 토성 → 천왕성 → 해왕성 → 명왕성 → 외계행성 → 심우주 N…`

| 요소 | 변화 |
|---|---|
| 행성 크기 / 궤도 반경 | 점점 작아짐 |
| 행성 간 거리 / 좌우 편차 | 점점 멀어짐 |
| 조준 표시선 | 지구(스테이지 1)에서만 |
| 소행성 | 스테이지 2부터 |
| 이동 행성 | 스테이지 3부터 |
| **화면 자동 상승** | **스테이지 4부터, 22 → 50px/s** |
| 붕괴 행성 | 스테이지 5부터 |

**보석 · 상점** — 행성 사이 길목에 보석이 떠 있어요 (행성당 `GEM_CHANCE` = 6%,
행성 25개당 평균 1.5개). 주운 보석은 **판이 끝날 때** 지갑으로 들어가고, 죽어도 사라지지 않아요.
우주선 스킨은 개당 100개(`SKIN_PRICE`)이고, 기본 스킨을 포함해 7종이에요.
성능 차이는 없어요 — 순전히 외형입니다.

**이어하기** — 광고를 끝까지 보면 마지막으로 밟았던 행성에서 다시 시작해요.
점수와 스테이지는 유지되고, 2.2초 무적 + 주변 소행성 제거가 붙어요. 한 판에 1회
(`MAX_REVIVES`, `src/config.js`).

버튼은 광고 로드가 끝나기 전이라도 보여줘요. 아직 로드 중이면 누른 뒤에 최대 4초를 기다리고,
그래도 안 되면 안내만 띄우고 기회는 그대로 남겨둬요. 로드 완료를 조건으로 걸면 네트워크가
느릴 때 기회가 조용히 사라지거든요.

> 로컬 개발(`npm run dev`)에서는 SDK가 없어 **가짜 광고**로 대체돼요. 버튼 → 0.9초 → 보상
> 지급까지 실제와 같은 흐름을 눌러볼 수 있어요. 프로덕션 번들에는 들어가지 않아요.

## 밸런스 조정

난이도 수치는 전부 `src/game.js`의 `diff(stage)` 한 함수에 모여 있어요.

개발 모드에서는 콘솔 핸들이 열려요.

```js
window.__spacejump   // { game, audio, showGameOver, startGame, records }
window.__spacejump.game.step(1/60)   // 렌더링과 무관하게 한 프레임 진행
window.__spacejump.game.jump()
```

### 밸런스 검증 (봇 시뮬레이션)

`step(dt)`로 결정론적 시뮬레이션이 가능해서, 봇을 붙여 난이도를 수치로 확인할 수 있어요.
가장 좁은 화면 비율(`H = 720`) 기준 측정값이에요.

| 봇 | 결과 |
|---|---|
| 타이밍이 완벽한 봇 | 76초 / 65개 착지 / 5,730점 / 스테이지 9에서 소행성 충돌 |
| 점프마다 0.8초 머뭇거리는 봇 | 43초 / 26개 착지 / 스테이지 4, 화면 아래까지 여유 최소 141px |
| 점프마다 1.4초 머뭇거리는 봇 | 61초 / 19개 착지 / 스테이지 3 |

세로가 긴 기기일수록 `H`가 커져서 화면 아래까지의 여유가 늘어나요. 위 수치가 가장 빡빡한 조건입니다.
