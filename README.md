# 궤도탈출 — 우주 점프 (앱인토스 미니앱)

지구에서 출발해 행성에서 행성으로 점프해 나가는 **Orbit / Circle Jump** 장르 게임.
앱인토스 **WebView 미니앱**(SDK 3.x)으로 만들어져 있고, 그대로 `.ait` 번들을 뽑아 콘솔에 올릴 수 있어요.

일반 브라우저에서도 그대로 돌아가요. SDK 기능(식별키 · 저장소 · 햅틱 · 광고 · 화면 제어)은
토스 앱 밖에서는 자동으로 대체 구현으로 떨어집니다.

---

## 빠르게 시작하기

```bash
npm install
npm run dev            # http://localhost:5173
npm run build          # dist/ 생성 후 orbit-jump.ait 패키징
npm run build:release  # 위 + orbit-jump_2.0v.ait 사본까지
```

`npm run build`가 끝나면 프로젝트 루트에 **`orbit-jump.ait`** 가 생겨요.
이 파일을 앱인토스 콘솔 → **앱 출시** 메뉴에 업로드하면 QR로 토스 앱에서 테스트할 수 있어요.

### 버전별 번들 보관

`ait build`는 **언제나 `orbit-jump.ait` 하나만** 만들어서 직전 번들을 덮어써요.
콘솔에 올린 제출본과 다음 버전을 같이 들고 있으려면(심사 중 롤백·비교) 사본이 필요해요.

`npm run build:release`를 쓰면 빌드가 끝난 뒤 `scripts/package-ait.mjs`가
package.json의 `version`을 붙인 사본을 하나 더 남겨요.

| 파일 | 내용 |
|---|---|
| `orbit-jump_1.0v.ait` | 최초 제출본 |
| `orbit-jump_1.1v.ait` | **현재 제출본** (본편만) |
| `orbit-jump_2.0v.ait` | 스토리 모드가 들어간 버전 |
| `orbit-jump_2.1v.ait` | 100행성 완주 구조 + 최종 보스전 (스토리 모드 잠금) |
| `orbit-jump.ait` | 마지막 빌드 결과 (`ait deploy`가 올리는 파일) |

버전을 올릴 때는 `package.json`의 `version`만 바꾸면 파일 이름이 따라와요.
(`2.0.0` → `orbit-jump_2.0v.ait`)

## 프로젝트 구조

```
apps-in-toss.config.ts   앱인토스 설정 (appName · 내비게이션 바 · WebView 옵션)
vite.config.js           번들러 설정
index.html               캔버스 + DOM 오버레이 UI 껍데기
introduce.html           게임 소개 · 홍보용 단일 페이지
supabase/schema.sql      DB 테이블 정의 (한 번만 실행)
scripts/package-ait.mjs  빌드된 .ait를 버전 이름으로 복사
src/
├─ main.js               부트스트랩 — 미니앱 수명주기와 게임을 연결
├─ game.js               게임 본체 (물리 · 렌더 · HUD · 보석)
├─ skins.js              우주선 스킨 7종 (전부 캔버스 드로잉)
├─ platform.js           앱인토스 SDK 어댑터 (브라우저 폴백 포함)
├─ cloud.js              Supabase 연동 (프로필 · 기록 · 랭킹)
├─ nickname.js           닉네임 생성 · 욕설 필터 · 검증
├─ audio.js              WebAudio 신스 — 효과음 · 공간계 · BGM
├─ config.js             광고 ID · 보석 확률 · DB 주소 등 출시 전 확인할 값
├─ style.css             오버레이 UI 스타일
│
│  ── 스토리 모드 (2.0)
├─ story.js              스토리 엔진 (대사 진행 · 슈팅 · 보스 · 배경 연출)
├─ story-script.js       대본 — 대사를 고칠 때는 여기만 보면 돼요
├─ story-cast.js         등장인물 초상화 (캔버스 벡터)
└─ viewport.js           캔버스 좌표계 · 백버퍼 관리 (스토리 모드 전용)
```

게임 코드는 SDK를 직접 부르지 않고 **전부 `platform.js`를 거쳐요.** SDK 버전이 바뀌거나
API 이름이 달라져도 이 파일 하나만 고치면 됩니다.

### 데이터베이스 (Supabase)

**처음 한 번은 반드시 직접 실행해야 해요.** publishable 키로는 테이블을 만들 수 없어요.

1. Supabase 대시보드 → **SQL Editor** → New query
2. `supabase/schema.sql` 전체를 붙여넣고 **Run**
3. 게임을 새로고침하면 랭킹이 뜨기 시작해요

> `permission denied for table players` (코드 42501)가 뜬다면 권한이 빠진 거예요.
> RLS 정책과 별개로 `anon` 역할에 테이블 GRANT가 있어야 PostgREST가 읽고 씁니다.
> `supabase/grants.sql`만 따로 실행하면 해결돼요.

| 테이블 | 담는 것 |
|---|---|
| `players` | 유저 식별키 · 닉네임(unique) · 보석 · 최고 기록 · 보유/장착 스킨 |
| `runs` | 한 판이 끝날 때마다의 기록 (점수 · 스테이지 · 보석 · 사망 사유) |

실행하기 전에도 **게임은 그대로 돌아가요.** 기록은 기기에 저장되고, 랭킹 화면에만
"아직 준비되지 않았어요"가 떠요. 서버가 죽어도 마찬가지예요.

동기화 규칙 — 로컬이 항상 먼저이고 서버는 백업이에요. 최고 기록은 큰 쪽을 남기지만,
**보석은 쓰는 재화라 max로 합치면 안 돼요** (기기 두 대로 같은 보석을 무한히 쓸 수 있어요).
그래서 서버 값을 따르되, 아직 못 올린 변화가 로컬에 있으면(`dirty`) 로컬을 지켜요.

> ⚠️ 로그인 절차가 없어서 클라이언트가 올리는 점수를 그대로 믿는 구조예요.
> 랭킹에 상금이 걸리는 등 신뢰가 중요해지면 Edge Function으로 검증을 옮기세요.

### 닉네임

정하지 않은 사람은 `우주미아0000` 형태를 자동으로 받아요. 식별키에서 번호를 뽑아
같은 사람은 늘 같은 이름이 되고, 겹치면 번호를 바꿔가며 최대 5번 다시 시도해요.

직접 지을 때는 한글·영문·숫자 2~12글자만 받고, `src/nickname.js`의 필터가
욕설·사칭어를 막아요. 숫자나 기호를 끼워 넣는 우회(`시1발`, `f u c k`)도 잡도록
비교 전에 공백·숫자·기호를 걷어내요. 중복은 DB의 unique 제약이 최종 심판이에요.
(확인과 저장 사이에 남이 먼저 가져갈 수 있어서, 저장 실패도 따로 안내해요.)

### 아이콘 규칙

**시스템 이모지를 쓰지 않아요.** 이모지는 기기·OS 버전마다 모양과 색이 달라서 같은 화면이
사람마다 다르게 보이거든요. 그래서 모든 아이콘은 직접 그려요.

| 자리 | 방식 |
|---|---|
| 홈 버튼 (설정 · 상점 · 랭킹) | `index.html`의 인라인 SVG. **테두리 선 자체가 톱니바퀴 · 장바구니 · 트로피 모양**이에요 (사각형 안에 아이콘을 넣은 게 아니에요) |
| 신기록 반짝임 | `style.css`의 `clip-path`로 그린 별 |
| 경고 표지 | `game.js`의 `drawWarnSign()` — 캔버스에 직접 |
| 소개 페이지 삽화 | `introduce.html` 안의 캔버스 드로잉 |

## 출시 전에 꼭 해야 하는 일

### 1. `appName` 맞추기

콘솔에 앱을 등록할 때 입력한 `appName`과 아래 두 곳이 **완전히 같아야** 해요.

- `apps-in-toss.config.ts` → `appName`
- `src/config.js` → `APP_NAME`

지금은 둘 다 `orbit-jump`로 되어 있어요. 딥링크도 `intoss://orbit-jump`가 됩니다.

### 2. 리워드 광고 ID 교체하기

현재는 문서에 공개된 **테스트 ID**(`ait-ad-test-rewarded-id`)를 쓰고 있어요.

```bash
cp .env.example .env.production
# VITE_REWARD_AD_GROUP_ID=콘솔에서_발급받은_보상형_광고_그룹_ID
npm run build
```

> 테스트 ID로 출시하면 수익이 잡히지 않고, 반대로 **실제 ID로 개발 테스트를 반복하면 정책 위반**이에요.
> 개발 중에는 테스트 ID를 그대로 두세요.

### 3. 콘솔에서 설정해야 하는 것

코드로는 할 수 없고 콘솔에서만 되는 것들이에요.

| 항목 | 위치 | 안 하면 생기는 일 |
|---|---|---|
| 카테고리를 **게임**으로 등록 | 미니앱 정보 | `getUserKeyForGame`이 `INVALID_CATEGORY` 반환, 리더보드 동작 안 함 |
| 앱 아이콘 · 국문 이름 | 미니앱 정보 | 미니앱 목록·공유에 브랜드가 안 나옴 (내비게이션 바 제목은 `withTitle: false`로 꺼둠) |
| 스크린샷 · 연령등급 · 개인정보처리방침 | 미니앱 정보 | 검수 반려 |
| 보상형 광고 단위 생성 | 인앱 광고 | 광고가 로드되지 않아 "이어하기" 버튼이 아예 안 뜸 |
| 게임 리더보드 활성화 | 게임센터 | 랭킹 화면의 "토스 게임센터 랭킹" 버튼이 숨겨짐. 자체 랭킹(Supabase)은 그대로 동작 |
| 고객센터 문의 채널 | 미니앱 정보 | 더보기 → 문의하기가 비어 있음 |

미니앱 정보 승인에는 영업일 기준 1~2일이 걸려요. 승인 전에는 리더보드 호출이 실패합니다.

## 게임 출시 가이드 대응표

[게임 출시 가이드](https://developers-apps-in-toss.toss.im/checklist/app-game) 항목별로 어디서 처리했는지 정리했어요.

### 접속 및 사운드

| 항목 | 구현 |
|---|---|
| 10초 이내 최초 화면 | 정적 번들(JS 약 110KB), 외부 요청 없음 |
| 배경음 · 효과음 · 햅틱 | `src/audio.js` (WebAudio 신스 BGM + SFX), `platform.haptic()` |
| 사용자가 사운드 On/Off | 홈 우측 톱니바퀴 → 설정에서 효과음 · 배경음 · 진동을 따로 끄고 마스터 볼륨을 조절해요. 세이브에 저장돼 다음 접속에도 유지 |
| 백그라운드 전환 시 사운드 즉시 종료 | `onVisibility` → `audio.suspend()` (AudioContext까지 정지) |
| 복귀 시 정상 재생 | `audio.resume()` + "이어서 하기" 화면 |

### UX 및 내비게이션 바

| 항목 | 구현 |
|---|---|
| 우측 상단 닫기 버튼 | 프레임워크 기본 제공. `navigationBar.transparentBackground` + `theme: 'dark'` |
| 좌측 상단 뒤로가기 · 제목 없음 | `withBackButton: false` + `withTitle: false`. 단일 화면이라 뒤로 갈 곳이 없고 제목 줄이 게임 상단을 덮어서 |
| Safe Area 침범 금지 | `SafeAreaInsets.get/subscribe` → CSS 변수 + 캔버스 HUD 좌표에 모두 반영 |
| X 버튼과 겹치는 UI 없음 | HUD는 좌측 열에만, 사운드 토글은 좌측 하단. 우측 상단 `NAV_RESERVE_W`는 비워둠 |
| 진입 즉시 바텀시트 없음 | 별도 시작 화면 없이 게임 화면 위에 홈 레이어만 얹혀요 |
| 모든 화면에서 나갈 수 있음 | 프레임워크 X + 뒤로가기 → 종료 확인 모달 |
| CTA 예측 가능 | 홈 "화면을 탭하여 시작" / 일시정지 "이어하기 · 홈으로 이동" / 게임 오버 "광고보고 부활하기 · 재도전하기 · 홈으로 이동" |
| 자사 서비스 유도 없음 | 외부 링크 없음 |
| 광고를 인트로·로딩·모달에 노출 안 함 | 게임 오버 화면에서 사용자가 직접 누를 때만 재생 |

| 항목 | 구현 |

| 플레이 기록 유지 | 최고 점수 · 최고 콤보 · 플레이 횟수를 `Storage`에 사용자 키별로 저장 |
| 재접속 후에도 유지 | `Storage` + `localStorage` 이중 저장 |

### 보안 및 안정성

| 항목 | 구현 |
|---|---|
| `eval` 등 외부 코드 실행 없음 | 없음 |
| `location.replace` 등 히스토리 조작 없음 | 없음 |
| SSR 미사용 | Vite 정적 빌드(CSR/SSG) |
| WebSocket | 사용하지 않음 (네트워크 요청 자체가 없음) |

### 서비스 이용 동작

| 항목 | 구현 |
|---|---|
| 인게임 풀스크린 | 논리 가로폭 480 고정 + 세로는 기기 비율을 따라감(`H_MIN`~`H_MAX`). 여백 없이 꽉 참 |
| 세로 모드 고정 | `Screen.setOrientation({ type: 'portrait' })` |
| 운영체제 뒤로가기 제스처 차단 | `Screen.setIosSwipeBack({ isEnabled: false })` + `webView.allowsBackForwardNavigationGestures: false` |
| 인터랙션 지연 없음 | 캔버스 60fps, 네트워크 대기 없음 |
| 권한 요청 없음 | `permissions: []` |
| 종료 시 확인 모달 | `graniteEvent.backEvent`를 가로채 확인 모달 → `Screen.close()` |
| 점수 · 스테이지 흐름 오류 없음 | 봇 시뮬레이션으로 검증 (아래 "밸런스 검증" 참고) |

### 캔버스 해상도 — 건드리기 전에 읽어주세요

한때 **모바일에서만** 게임 화면이 화면 해상도의 1/3로 그려졌어요. DOM(버튼·토글)은 멀쩡한데
캔버스만 뭉개져서 원인 찾기가 까다로웠습니다. 스크린샷 픽셀의 인접 차분이 3개씩 묶여
같은 값으로 나오는 것(= 3픽셀 간격 선형 보간)으로 배율을 역산해 확인했어요.

원인은 하나가 아니라 세 겹이었고, `src/game.js`의 `resize()` 주변이 전부 그 대응이에요.

| 함정 | 대응 |
|---|---|
| 웹뷰가 로드 직후 `devicePixelRatio`를 1로 보고했다가 나중에 제값을 줌. `resize()`는 한 번만 돌아서 1로 굳음 | `draw()` 맨 앞 `ensureBackingStore()` — 매 프레임 정수 비교 두 번으로 어긋나면 다시 잡음 |
| `devicePixelRatio` 하나만 믿음 | `ResizeObserver`의 `device-pixel-content-box` 실측을 1순위로, CSS `min-resolution` 이분 탐색을 2순위로. 그래도 1이고 화면이 좁으면 3배를 깖 |
| `visualViewport` 값대로 캔버스가 그려질 거라 **가정**하고 좌표계를 세움 | `style`을 먹인 뒤 `getBoundingClientRect()`로 되재서, 논리 높이·배율·여백·백버퍼를 전부 실측값 위에서 계산 |

`#game`이 `position: absolute`인 것도 의도예요. WebKit이 `fixed` 요소를 별도 합성 레이어로
올리면서 래스터화 배율을 백버퍼 크기와 무관하게 잡는 경우가 있어요. `fixed`로 되돌리지 마세요.

재발하면 `game.renderInfo()`를 설정 화면 같은 데 찍어보면 돼요. `actualRatio`가 기기 배율과
같아야 정상이고, `css`와 `askedCss`가 다르면 레이아웃이 어긋난 거예요.

### 인앱 광고

| 항목 | 구현 |
|---|---|
| 광고 중 음악 일시정지 | `game.pause()` + `audio.suspend()` |
| 예상 못 한 순간에 노출 안 함 | 사용자가 "광고 보고 이어하기"를 직접 눌렀을 때만 |
| 사전 로딩 | 게임 시작 시 · 광고 종료 직후 `preload()`. 로드가 늦어도 버튼은 보여주고 누른 뒤 최대 4초 기다려요 |
| 종료 후 미니앱 복귀 | `dismissed` 처리 + 안드로이드 `dismissed` 누락 대비 `visibilitychange` 폴백 |
| 종료 후 음악 재개 | `audio.resume()` |
| 끝까지 봐야 보상 지급 | `userEarnedReward` 이벤트에서만 `game.revive()` 호출 |

## 기기에서 꼭 직접 확인해야 하는 것

문서만으로는 확답이 안 되는 항목이에요. QR 테스트 때 눈으로 확인해 주세요.

1. **내비게이션 바 X 버튼을 눌렀을 때 종료 확인 모달이 뜨는지.**
   X 버튼이 `backEvent`를 발생시키는지는 문서에 명시돼 있지 않아요.
   바로 닫힌다면 검수 대응을 위해 채널톡으로 문의가 필요할 수 있어요.
   (뒤로가기 버튼 · 제스처는 모달을 확실히 거칩니다.)
2. **햅틱이 과하지 않은지.** 착지마다 `tickWeak`이 울려요. 거슬리면 `src/game.js`의 `haptic(...)` 호출을 줄이세요.
3. **광고 로드 소요 시간.** 애드몹이 선택되면 최대 60초까지 걸릴 수 있어요. 그동안은 "이어하기" 버튼이 안 보입니다.
4. **노치 · 다이내믹 아일랜드 기기에서 HUD 위치.**

## 게임 규칙

1. 우주선은 행성의 점선 궤도를 따라 공전해요.
2. 탭하면 **우주선이 향한 직선 방향(행성 중심 → 우주선)** 그대로 발사돼요.
3. 다음 행성의 점선 궤도 안에 들어가면 자동으로 착지해요.
4. 빗나가면 그대로 우주 밖으로 날아가 실패해요. (벽에 튕기지 않아요)
5. **목성(스테이지 4)부터 화면이 저절로 계속 위로 올라와요.** 아래로 밀려나면 끝이에요.
6. **행성 100개를 지나면 끝이에요.** 마지막 「관문」에서 최종 보스전이 열립니다.

실패 유형: `추락` · `궤도 이탈` · `우주 미아` · `소행성 충돌` · `행성 붕괴` · `화면 밖으로 밀려남`

**점수** — 착지 = `10 × 콤보 배수`(최대 x9), 정밀 착지 `PERFECT!` +15, 체크포인트 행성 +30.
3.4초 안에 다음 행성을 잡으면 콤보가 이어져요.

**스테이지** — 행성 10개(`PLANETS_PER_STAGE`)마다 상승. 총 10스테이지 · 100행성(`TOTAL_PLANETS`)이 게임의 끝이에요.
`지구 → 달 → 화성 → 목성 → 토성 → 천왕성 → 해왕성 → 명왕성 → 외계행성 → 관문`

**진행 대시보드** — 화면 위쪽에 `스테이지 이름 · STAGE n` / `행성 n / 100`과 진행 막대가 늘 떠 있어요.
막대의 눈금 10칸이 스테이지 경계고, 그 아래에 점수 · 보석 · 콤보가 쌓여요.

| 요소 | 변화 |
|---|---|
| 행성 크기 / 궤도 반경 | 점점 작아짐 |
| 행성 간 거리 / 좌우 편차 | 점점 멀어짐 |
| 조준 표시선 | 지구(스테이지 1)에서만 |
| 소행성 | 스테이지 2부터 |
| 이동 행성 | 스테이지 3부터 |
| **화면 자동 상승** | **스테이지 4부터, 22 → 50px/s** |
| 붕괴 행성 | 스테이지 5부터 |

**보석 · 상점** — 행성 사이 길목에 보석이 떠 있어요 (행성당 `GEM_CHANCE` = 6%,
행성 25개당 평균 1.5개). 주운 보석은 **판이 끝날 때** 지갑으로 들어가고, 죽어도 사라지지 않아요.
우주선 스킨은 개당 100개(`SKIN_PRICE`)이고, 기본 스킨을 포함해 7종이에요.
성능 차이는 없어요 — 순전히 외형입니다.

**이어하기** — 광고를 끝까지 보면 마지막으로 밟았던 행성에서 다시 시작해요.
점수와 스테이지는 유지되고, 2.2초 무적 + 주변 소행성 제거가 붙어요. 한 판에 1회
(`MAX_REVIVES`, `src/config.js`).

버튼은 광고 로드가 끝나기 전이라도 보여줘요. 아직 로드 중이면 누른 뒤에 최대 4초를 기다리고,
그래도 안 되면 안내만 띄우고 기회는 그대로 남겨둬요. 로드 완료를 조건으로 걸면 네트워크가
느릴 때 기회가 조용히 사라지거든요.

> 로컬 개발(`npm run dev`)에서는 SDK가 없어 **가짜 광고**로 대체돼요. 버튼 → 0.9초 → 보상
> 지급까지 실제와 같은 흐름을 눌러볼 수 있어요. 프로덕션 번들에는 들어가지 않아요.

## 최종 보스전 — 「가디언-00 · 오버시어」 (2.1)

100번째 행성 「관문」에 착지하면 본편은 거기서 끝나요.
`마지막 행성에 도달했습니다` 연출(2.6초) 뒤에 **스토리 모드와 같은 슈팅 엔진**이 열리고,
관문지기 「가디언-00 · 오버시어」(체력 `FINAL_BOSS_HP` = 460)를 격파하면 게임 클리어예요.

| 흐름 | 무엇이 일어나나 |
|---|---|
| `game.js` | 행성 index 99 착지 → `state.mode = 'final'` → `onFinalPlanet(결과)` |
| `main.js` | `startFinalBoss()` — 본편은 그리기만 끄고, 스토리 캔버스를 띄워요 |
| `story.js` | `startFinalBoss({carryScore})` — 비행 구간 없이 보스부터. 배경은 「관문」(`bg: 'deep'`) |
| 클리어 | `onFinalClear` → **총점 = 본편 점수 + 보스전 점수**. 랭킹에 이 총점을 올려요 |
| 실패 | `onFinalFail` → 점수는 그대로 기록하고, **관문만** 다시 도전할 수 있어요 (본편 점수 유지) |

두 모드의 차이는 `story.js`의 `RUNS` 한 곳에 모여 있어요. (배경 · 보스 이름 · 체력 · 대사 · 스폰 여부)
`window.__spacejump.finalBoss()` 로 100행성을 돌지 않고 바로 열어볼 수 있어요. (개발 빌드 전용)

클리어 여부(`cleared`) · 클리어 횟수 · 최고 도달 행성은 세이브에 남고, 홈 화면에 표시돼요.

## 스토리 모드 (2.0) — **2.1 출시본에서는 잠겨 있어요**

> `src/config.js`의 `STORY_LOCKED = true` 인 동안에는 진입 버튼이 "준비 중"으로 보이고,
> 누르면 `스토리 모드는 추후 업데이트 예정입니다.` 안내만 떠요.
> 다음 업데이트에서 이 값을 `false`로 되돌리면 아래 내용 그대로 열려요.
> 엔진 자체는 **최종 보스전이 쓰고 있어서** 번들에 그대로 들어 있어요.

첫 화면의 **스토리 모드** 버튼, 또는 홈 우측의 말풍선 아이콘으로 들어가요.
본편과 **완전히 분리된 엔진**이에요 — 캔버스(`#story`)도 게임 루프도 따로 씁니다.
출시된 본편(`game.js`)의 렌더링 코드를 건드리지 않으려고 일부러 이렇게 나눴어요.
스토리가 켜지면 본편은 `setRenderEnabled(false)`로 **그리기만** 멈춰요.
(캔버스를 `display:none`으로 감추면 크기가 0으로 측정돼서 돌아왔을 때 한동안 뭉개져요)

### STAGE 1 「지구 → 달」

| 구간 | 내용 |
|---|---|
| 1. 인트로 | 2045년, 자기권이 무너진 지구. 사이렌이 울리고 관제 AI가 이탈을 명령해요. 한도윤(조종사) · 유서린(항법사)이 달의 셀레네 기지로 향하기로 합니다. |
| 2. 비행 | 세로 스크롤 슈팅. 지구를 등지고 올라가며 잔해 · 기뢰 · 무인 정찰기 · 요격기를 뚫어요. 약 55초. |
| 3. 보스 | 달 궤도 방어 위성 **「가디언-01」**. 체력 3구간마다 패턴이 바뀌어요 (부채꼴 산탄 → 나선탄 + 요격기 소환 → 조준 레이저). |
| 4. 착륙 | 달에 내려앉지만 셀레네 기지의 불은 모두 꺼져 있어요. STAGE 2로 이어지는 마무리. |

조작은 **화면을 끌어서** 기체를 옮기는 것뿐이에요. 사격은 자동입니다.
손가락이 기체를 가리지 않게, 잡은 순간의 간격을 그대로 유지해요.
방패(피격 허용)는 5칸이고 맞으면 1.5초 무적 + 주변 탄이 지워져요.

### 고치는 자리

| 무엇을 | 어디를 |
|---|---|
| 대사 · 이름 · 스테이지 표지 | `src/story-script.js` (데이터만 있어요) |
| 인물 생김새 · 색 | `src/story-cast.js` |
| 적 배치 · 등장 시각 | `src/story.js`의 `SCHEDULE` |
| 보스 체력 · 패턴 | `src/story.js`의 `BOSS_HP`, `updateBoss()` |
| 점수 | `src/story.js`의 `SCORE` |

인물 · 배경 · 적 모두 **이미지 파일 없이 캔버스 벡터로** 그려요. 본편과 같은 이유예요 —
`.ait` 용량이 늘지 않고, 어떤 해상도에서도 뭉개지지 않아요.

스토리 진행 기록(클리어 여부 · 최고 점수)은 **이 기기에만** 저장돼요.
본편 랭킹·보석과 성격이 달라서 서버(Supabase)에는 올리지 않습니다.

### 스토리 모드 검증

본편과 마찬가지로 `step(dt)`로 렌더링과 무관하게 진행시킬 수 있어요.

```js
window.__spacejump.openStory(true)          // 인트로 건너뛰고 비행부터
const s = window.__spacejump.story
for (let i = 0; i < 60 * 90; i++) s.step(1/60)
s.state.phase, s.state.score
```

완벽하게 조준하는 봇 기준 측정값이에요.

| 지점 | 시각 |
|---|---|
| 보스 등장 | 57.4초 |
| 2페이즈 (체력 66%) | 65.5초 |
| 3페이즈 (체력 33%) | 75.3초 |
| 가디언 격파 | 89.8초 |

즉 비행 55초 + 보스 32초예요. 여기에 인트로 · 착륙 대사를 더하면 한 판이 3~4분입니다.

### 밸런스 검증 (봇 시뮬레이션)

`step(dt)`로 결정론적 시뮬레이션이 가능해서, 봇을 붙여 난이도를 수치로 확인할 수 있어요.
가장 좁은 화면 비율(`H = 720`) 기준 측정값이에요.

| 봇 | 결과 |
|---|---|
| 타이밍이 완벽한 봇 | 76초 / 65개 착지 / 5,730점 / 스테이지 9에서 소행성 충돌 |
| 점프마다 0.8초 머뭇거리는 봇 | 43초 / 26개 착지 / 스테이지 4, 화면 아래까지 여유 최소 141px |
| 점프마다 1.4초 머뭇거리는 봇 | 61초 / 19개 착지 / 스테이지 3 |

세로가 긴 기기일수록 `H`가 커져서 화면 아래까지의 여유가 늘어나요. 위 수치가 가장 빡빡한 조건입니다.
